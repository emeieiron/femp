# Build outputs and bindings

`femp build` compiles every platform module and writes what each platform needs to use it:

```text
build/evm/<module>/      <Contract>.bin  .runtime.bin  .abi.json  .metadata.json  <Contract>.ts
build/native/<module>/   <ingot name>
build/wasm/<module>/     <ingot name>.wasm  .manifest.json  .js  .d.ts  host.js  host.d.ts  package.json
```

`-O 0`, `1` (the default), `2` or `s` sets the optimization level, and `-t` limits the build to
some platforms. Bindings are generated by default; `[platform.<id>]` in `femp.toml` selects
them:

```toml
[platform.wasm]
bindings = ["typescript"]   # [] turns generation off
```

## EVM contracts

For every contract of the module, `femp build` writes what `fe build` writes, byte for byte:
creation and runtime bytecode as hex, the JSON ABI, and the contract's metadata. It adds a
TypeScript module with the ABI `as const`, both bytecodes, and types derived from the ABI:

```ts
// Generated by femp. Do not edit: changes are overwritten on the next build.

export const vestingAbi = [ /* the ABI */ ] as const;
export const vestingBytecode = "0x60e0…" as const;
export const vestingDeployedBytecode = "0x3660…" as const;

export type VestingConstructorArgs = [total: bigint, start: bigint, cliff: bigint, duration: bigint];

export interface VestingFunctions {
  /** view */
  vestedAt(timestamp: bigint): bigint;
  /** nonpayable */
  claim(amount: bigint): bigint;
  // ...
}

export interface VestingEvents {
  TokensClaimed: { amount: bigint; total_claimed: bigint };
}

export interface VestingErrors {
  VestingFailed: { code: number };
}
```

Because the ABI is a constant, libraries that infer types from it check calls at compile
time. With viem:

```ts
import { vestingAbi, vestingBytecode } from "./build/evm/contracts/Vesting";

const hash = await wallet.deployContract({
  abi: vestingAbi,
  bytecode: vestingBytecode,
  args: [1000n, 0n, 0n, 100n],
});

const claimable = await client.readContract({
  address,
  abi: vestingAbi,
  functionName: "claimable",
});
```

A function's name and parameter types come from its message variant's
`#[selector = sol("…")]`; a variant without one is left out of the ABI. State mutability
follows the handler's effects: `pure` with none, `view` when it uses them only immutably,
`nonpayable` when it uses one mutably, and `payable` for a `#[payable]` handler.

## Native programs

A `native` module builds into one executable, named after its ingot and linked with the
system's C compiler. Its root file declares `main`, which takes what it needs as effects:

```fe
use std::env::Args
use std::io::{Stderr, Stdout}

pub fn main() -> i32 uses (args: Args, out: mut Stdout, err: mut Stderr) {
    // ...
}
```

`main` returns the process's exit status. `femp package` places the executable under
`dist/native/<arch>-<os>/`, such as `aarch64-macos`.

## WebAssembly modules

A `wasm` module builds into one WebAssembly module with its dependencies, plus the
compiler's build manifest. Every non-generic `pub fn` in its root file is exported:

```fe
// wasm/src/lib.fe
pub fn vested_at(total: u64, start: u64, cliff: u64, duration: u64, now: u64) -> u64
uses (host: mut Abort) {
    schedule_or_abort(total, start, cliff, duration).vested_at(now)
}
```

The generated class loads the module next to it and exposes each export as a method, in camel
case:

```js
import { VestingWeb } from "./build/wasm/web/vesting_web.js";

const vesting = await VestingWeb.load();
vesting.vestedAt(1000n, 0n, 0n, 100n, 50n); // 500n
```

| Fe | JavaScript |
| --- | --- |
| `bool` | `boolean` |
| `u8`…`u32`, `i8`…`i32`, `usize`, `isize` | `number` (`usize` is 32 bits in WebAssembly) |
| `u64`, `i64` | `bigint` |
| `std::wasm::HostText` parameter | a string or `Uint8Array`, at most 64 KiB, placed in the module's memory for one call |
| `std::wasm::Reply` result | `{ ok: true, value }` or `{ ok: false, code }` |

### The host runtime

`host.js` implements Fe's WebAssembly host contract, has no dependencies, and runs in browsers
and in Node.js 20 or newer. `load()` takes an optional source and host options:

```js
const app = await MyAppWeb.load(fetch("/my_app_web.wasm"), {
  now: () => Date.now(),                  // the Clock the module reads
  onLog: (value) => console.debug(value), // values the module logs
  files: { "rates.txt": "250\n" },        // read-only files the module may open
});
```

| | |
| --- | --- |
| Source | A URL (the default is the `.wasm` beside the class), a `Response`, bytes, or a promise of one. |
| Verification | Before instantiating, the host checks the module against its manifest: versions, SHA-256, imports and exports. In a browser this needs Web Crypto, so serve the page over HTTPS or from `localhost`. |
| Imports | `imports` adds implementations of the module's own imported functions. |
| Errors | `GuestAbort` when the module aborts through `std::wasm::Abort`, carrying its code; `ContractError` when the module or the caller breaks the host contract. |

Aborting with a code is the way to report a domain error to JavaScript:

```fe
fn schedule_or_abort(total: u64, start: u64, cliff: u64, duration: u64) -> Schedule
uses (host: mut Abort) {
    match Schedule::new(total, start, cliff, duration) {
        Result::Ok(schedule) => schedule,
        Result::Err(error) => host.abort(code: error.code()),
    }
}
```

```js
import { GuestAbort } from "./build/wasm/web/host.js";

try {
  vesting.vestedAt(0n, 0n, 0n, 100n, 50n);
} catch (error) {
  if (error instanceof GuestAbort) console.log(error.code); // 1: the total must be greater than zero
}
```

The output directory has a `package.json`, so it can be published or installed as an npm
package as it is.

## Packaging

```bash
femp package
```

`femp package` builds, then collects every platform's outputs under `dist/` with a manifest
of every file's kind and SHA-256:

```json
{
  "project": { "name": "my-app", "version": "0.1.0" },
  "compiler": "fe 26.6.0",
  "packages": [
    {
      "platform": "evm",
      "module": "contracts",
      "files": [
        { "path": "evm/contracts/Fees.bin", "kind": "bytecode", "sha256": "bcb285e4…" },
        { "path": "evm/contracts/Fees.ts", "kind": "binding", "sha256": "d540480f…" }
      ]
    }
  ]
}
```

| Platform | Kinds |
| --- | --- |
| `evm` | `bytecode`, `runtime-bytecode`, `abi`, `metadata`, `binding` |
| `native` | `executable` |
| `wasm` | `wasm-module`, `wasm-manifest`, `binding`, `runtime`, `package-manifest` |

`femp clean` removes `build/` and `dist/`.
